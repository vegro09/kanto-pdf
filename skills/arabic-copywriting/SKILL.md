## Purpose

Produce natively-written, tonally correct Arabic copy — not literal/machine-style translation — matched to the right register (Modern Standard Arabic vs. dialect) and with correct diacritics where precision matters.

## Core Principle: Write Natively, Don't Translate Literally

- Start from the intent/message, not the English sentence structure. Arabic sentence rhythm, emphasis, and idiom differ from English — a direct translation reads stiff and unnatural to native speakers.
- Research how a native Arabic speaker would actually search/say/write the concept, especially for product names, feature names, and keywords — don't assume literal translation matches real usage (e.g. "barter" as "مقايضة" vs. "تبادل" vs. "بدل" carry different connotations).

## Register: MSA vs. Dialect

- Default to Modern Standard Arabic (MSA / فصحى) for: app store listings, formal marketing, legal/policy text, brand descriptions, academic content — MSA is understood across all Arabic-speaking regions and is safer for broad reach and SEO.
- Consider dialect (e.g. Jordanian/Levantine) only for: casual social media captions, conversational UI microcopy, or when the brand voice is explicitly informal/local — confirm this fits the target audience first.
- Never mix MSA and dialect within the same piece of copy unless intentionally stylistic (e.g. a formal headline with a casual dialect tagline) — inconsistency reads as unpolished.

## Diacritics (تشكيل)

- Use diacritics precisely where ambiguity would otherwise cause misreading (religious/formal text, specific brand terms, poetry-style copy) — apply them exactly and correctly, not decoratively.
- For general UI/marketing copy, diacritics are typically omitted (standard practice) unless the brand/context specifically calls for them (as established in prior Play Store description work) — confirm which mode is expected before writing.
- Never guess a diacritic mark if unsure of the correct grammatical case — an incorrect diacritic is worse than none, since it signals a specific (and possibly wrong) grammatical reading to fluent readers.

## Tone & Brand Voice

- Match the established brand tone per project (e.g. Kanto Empire's elevated/sovereign tone vs. Baddil's approachable/practical tone vs. triohalf's punchy ad-agency tone) — don't default to one generic "professional Arabic" voice across all projects.
- Keep sentence length varied — Arabic marketing copy that uses only long, formal sentences reads as heavy; short punchy lines mixed with longer ones read as more modern and confident.

## Length & Layout Considerations

- Arabic text typically runs 20–30% longer than the English equivalent for the same meaning — account for this in any UI string, button label, or character-limited field (e.g. Play Store's 80-character short description).
- For character-limited fields (Play Store short description, meta descriptions, titles), write directly in Arabic and count Arabic characters — don't translate an already-tight English version and then try to trim it.

## RTL & Formatting

- Ensure numerals, punctuation, and any embedded English terms (brand names, technical terms) render correctly within RTL flow — test how mixed Arabic/English/numeral strings actually display, since bidi (bidirectional text) rendering can reorder unexpectedly.
- Arabic-Indic numerals (٠١٢٣) vs. Western numerals (0123): confirm project convention — most modern Arabic apps/UI use Western numerals for consistency with universal UI patterns unless the brand is intentionally traditional.

## SEO/ASO-Specific Arabic Considerations

- Research actual Arabic search terms/keywords natively (don't machine-translate English keyword research) — search behavior and phrasing often diverge significantly from literal translation.
- Common transliterations (e.g. English brand names written in Arabic script) should be checked for what users actually search, not just phonetically "correct" transliteration.

## Process

1. Confirm register (MSA vs. dialect) and brand tone before writing.
2. Write directly in Arabic from the intended message — do not draft in English and translate.
3. For character-limited fields, write and count in Arabic directly.
4. Apply diacritics only where grammatically necessary or explicitly requested.
5. Check mixed-content (numerals, English terms) rendering in RTL context.
6. Read the final copy aloud (mentally) as a native speaker would — if it sounds like a translation, rewrite it.
